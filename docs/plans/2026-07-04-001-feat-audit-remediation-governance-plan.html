Summary

Remediate the July 2026 audit findings across all three strategy tracks: a hard goal-drift guard in the loop driver (new exit code 8) backed by the plugin's first hook, a three-state evaluator gate on learning capture with confidence/provenance in the solutions schema, a run-progress file that lets retries resume instead of cold-restarting, a mechanical hygiene batch (manifests, dead CI, unwired agents, doc mirror, monolithic skills, beta twin), and behavioral eval suites for the four core skills. Every unit lands with contract-test verification under bun test.

Problem Frame

An audit against current Anthropic guidance (context engineering, long-running-agent harnesses, agent skills, memory) found the loop mechanics strongly aligned but the governance layer soft. "Goals change only with human approval" is enforced by convention and the PR merge gate — nothing stops an unattended run from editing STRATEGY.md or the plan mid-run, and the goal_fidelity metric is uninstrumented. Learnings are written by the same agent that did the work; Anthropic's harness guidance is explicit that generators reliably over-praise their own output, so unverified learnings enter docs/solutions/ as truth. Retries cold-restart from step 1 because lfg has no resume entry point, and lfg step 10 / sl-learn detect CI state via a fragile PR-body substring. Hygiene drift accumulated: stale manifest keywords, a dead docs workflow, two never-dispatched agents, a hand-maintained skills mirror with eight broken links, four monolithic skills, and a beta twin past its trial window. No behavioral evals exist for the load-bearing skills, so self-improvement is asserted rather than measured.

Key Technical Decisions

KTD1 · Guard authority

The checksum guard in loop.sh is authoritative; the hook is defense-in-depth. PreToolUse on Write/Edit misses Bash writes (sed -i, redirection) and worktree merges (subagent edits merge back via git merge, bypassing tool interception). Only an end-of-run hash comparison catches every mutation path. The hook's value is failing fast and teaching the agent the boundary mid-run.

KTD2 · Hook activation

The hook is env-gated via LOOP_GOAL_GUARD_PATHS, set only by loop.sh. Plugin hooks fire in every session that loads the plugin; an always-on deny would break sl-strategy (whose job is writing STRATEGY.md) and interactive plan editing. The variable carries exact resolved paths — never docs/plans/**, since seed-mode runs must let sl-plan create a plan.

KTD3 · Drift is terminal, not retryable

Drift detected at a done_reached path exits 8 immediately. Retries exist for crash-without-DONE; a run that reached DONE with a mutated goal is a completed-but-untrustworthy run, matching the exit-7 (done-but-red) semantics. Checksums re-snapshot per attempt after reset_target restores the committed base.

KTD4 · Three-state learning verdict

Evaluator verdicts are verified / candidate / rejected, not pass/fail. Refute-by-default on diff+CI evidence alone would systematically reject work-phase learnings (debugging detours with no CI trace) — the class sl-learn exists to capture. Only affirmative refutation blocks a commit; unconfirmable learnings commit as candidate with lower retrieval weight. User-confirmed 2026-07-04.

KTD5 · Progress file lives outside the target tree

loop.sh owns the progress-file path (under its log directory) and passes it to lfg via a prompt marker. In-target placement fails twice: reset_target's git clean -fd deletes it on retry, and lfg step 8 "commit remaining changes" would sweep it into the PR. Matches the AGENTS.md scratch-space rule for cross-invocation state.

KTD6 · Resume scope is steps 1–7

Open-PR crash reconciliation keeps precedence; resume never fires once a PR exists. Post-PR resume would need the step-9 fix-iteration cap carried across attempts to avoid unbounded CI-fix looping — deferred. The counters are still recorded (R14) for observability and to power R17's substring-check replacement.

KTD7 · New exit path follows the run-record contract

Exit 8 extends the readonly block, the emit_record case map, the docs exit-code and typed_failure tables, and the operator wrapper capture in the same change. "The exit code is the API" — every terminal emits a run-record; failure records are the completion-rate denominator.

KTD8 · Generated index, curated pages

Only the docs/skills/README.md index is generated from frontmatter; per-skill pages stay hand-curated. Plugin AGENTS.md deliberately defines the mirror as high-level prose, not a SKILL.md mirror — full generation would be a convention change. Drift is killed where it is mechanical (coverage, links, descriptions) and left human where it is editorial.

KTD9 · Retire, don't merge, the reviewer fleets

Only the two genuinely unwired agents are removed. The wiring sweep showed the standalone analysts are all dispatched (sl-plan deepening, sl-compound validation) and the persona/analyst boundary is already documented in persona-catalog.md. A fleet merge would be scope without evidence of harm.

KTD10 · Schema fields are optional

confidence/provenance/evidence join the shared block as optional fields. The six existing docs stay valid (absent = legacy); retrieval treats absent as candidate-equivalent. Avoids a migration commit and the partial-validator hazard.

KTD11 · Evals go through the skill-creator workflow

Eval suites follow the sl-sessions/evals/ three-file structure and run via the skill-creator iteration workflow — the AGENTS.md-mandated path for behavioral validation (plugin prose caches at session start; editing the cache is banned). Each suite tests one narrow load-bearing assumption, not general skill quality.

Risks & Dependencies

Risk · Mitigated Stale progress file fakes a resume point. Shape + binding-field validation, scrub-on-every-terminal, and fail-safe cold restart (U8); resume never overrides the PR-reconciliation or retry caps, so the give-up floor is intact.
Risk · Mitigated New exit code breaks the observability contract. Exit 8 lands in the readonly block, emit_record, both docs tables, and the wrapper capture in one unit (U4/KTD7) with failure-path tests written first.
Risk · Open First plugin hook surface. The pinned CI validator (claude plugin validate @2.1.175) and release:validate surface counts may react to a new hooks/ dir — U5 verifies both; if the pinned CLI rejects hooks, bump the pin in the same PR.
Risk · Open Evaluator cost/latency inside the attempt wall-clock. A slow evaluator can push a green run into timeout after the PR opened (learning silently lost via reconciliation). Accepted for now: the window exists today; fail-toward-candidate keeps the loss honest. Revisit if dogfood runs show it firing.
Risk · Open Resume-mode prose complexity in lfg. A third input mode risks diluting the "execute in order" discipline; the carve-out is scoped to postcondition re-verification and the contract test (U6/U7) pins the language.
Dependency Release-owned files. The active release-as: 1.0.3 pin means no cleanup commit may touch version fields — U1 is scoped to content-only manifest edits per the version-drift learning.
